# D002 — Astro Static View first, Python contracts retained

**Date:** 2026-07-30  
**Owner:** Codex  
**Independent reviewer:** Claude  
**Status:** Adopted for Astro rendering and Static View sequencing. Python ownership is superseded by D003.

## Context

The current site is generated by a large Python file containing inline HTML and CSS. It has no tests or CI, is vulnerable to `/profile/` base-path mistakes and reports success when PDF generation fails. The newer Static View addendum requires semantic no-JavaScript HTML, conventional routes, responsive images, strong SEO and a strict future immersive loading boundary.

Three paths were compared:

1. Continue the current generator.
2. Refactor Python into the long-term HTML template renderer.
3. Use Astro for public HTML while retaining Python for validation and documents.

The independent weighted architecture review scored the hybrid path highest because it preserves the document investment while avoiding bespoke route, image, SEO and immersive-boundary infrastructure.

## Decision

- Astro and TypeScript become the sole public HTML renderer.
- TypeScript also owns production validation, manifest compilation and browser-native resume/CV generation, per D003.
- The existing Python asset-registry verifier remains an independent audit utility, not a production-build dependency.
- One route manifest and one compiled professional-content manifest feed both paths.
- Static View ships to production before immersive development begins.
- The production site remains at `https://bongo-seakhoa.github.io/profile/` unless the owner later requests a domain change.
- Static View contains no framework island, React dependency, canvas, WebGL or decorative motion.
- The future immersive entry point lives behind a separate opt-in import boundary.

## Consequences

Positive:

- Strong base-path handling and physical directory routes.
- Typed content and components.
- Built-in static rendering and responsive image integration.
- Clean SEO and sitemap generation.
- Browser QA and later Anzania work already share the Node toolchain.
- Current PDFs can migrate independently.

Costs:

- Node and Python are both required in development and CI.
- Project dependencies and a lockfile must be added.
- The existing page renderer is replaced, not gradually styled in place.
- CI must install browser dependencies.

## Rollback

The current production commit is tagged before Pages settings change. The legacy public artifact remains packageable for one stable release cycle. A failed release is rolled back by redeploying the last known-good artifact through the same GitHub Pages Actions path.
